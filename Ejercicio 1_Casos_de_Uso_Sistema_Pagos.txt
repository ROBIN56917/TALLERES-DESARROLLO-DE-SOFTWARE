1. CASO DE USO: PROCESAR PAGO
============================================================

Como cliente autenticado, quiero realizar el pago de una factura de servicios públicos desde mi cuenta, para cancelar el valor pendiente de la factura.

ACTORES PRIMARIOS:
- Cliente

ACTORES SECUNDARIOS:
- Sistema de Pagos
- Cuenta de Ahorros
- Cuenta Corriente
- Empresa de servicios públicos

PRECONDICIONES:
- El cliente debe estar registrado y autenticado.
- El cliente debe tener una cuenta activa.
- La factura debe existir.
- La factura debe estar pendiente de pago.
- La cuenta debe tener saldo suficiente para realizar el pago.

POSTCONDICIONES:
- El pago queda registrado.
- El saldo de la cuenta disminuye por el valor pagado.
- La factura queda marcada como pagada.
- El sistema genera un comprobante del pago.

FLUJO PRINCIPAL:
Given El cliente está autenticado y tiene una cuenta activa.
When El cliente selecciona la opción "Pagar factura".
Then El sistema solicita el número de factura.
Then El cliente ingresa el número de factura.
Then El sistema consulta la factura.
Then El sistema muestra los datos de la factura y el valor a pagar.
Then El cliente selecciona la cuenta desde la cual realizará el pago.
Then El sistema valida que la cuenta esté activa y tenga saldo suficiente.
Then El sistema muestra un resumen de la operación.
Then El cliente confirma el pago.
Then El sistema procesa el pago.
Then El sistema descuenta el valor de la cuenta.
Then El sistema actualiza la factura como pagada.
Then El sistema registra el pago.
Then El sistema muestra el comprobante de pago.

FLUJO ALTERNATIVO 1 - PAGO DESDE OTRA CUENTA:
Given El cliente tiene más de una cuenta activa.
When El cliente selecciona una cuenta para realizar el pago.
Then El sistema valida la cuenta seleccionada.
Then El cliente puede cambiar a otra cuenta disponible.
Then El sistema actualiza el resumen con la nueva cuenta.
Then El flujo continúa con la confirmación del pago.

FLUJO ALTERNATIVO 2 - CLIENTE CANCELA:
Given El sistema muestra el resumen del pago.
When El cliente decide cancelar la operación.
Then El sistema cancela la operación.
Then El sistema no modifica el saldo de la cuenta.
Then El sistema no modifica el estado de la factura.
Then El sistema regresa al menú principal.

EXCEPCIÓN 1 - FACTURA NO ENCONTRADA:
Given El cliente ingresa un número de factura inexistente.
When El sistema realiza la consulta.
Then El sistema informa "Factura no encontrada".
Then El sistema permite corregir el número de factura o cancelar la operación.

EXCEPCIÓN 2 - SALDO INSUFICIENTE:
Given La cuenta seleccionada no tiene saldo suficiente.
When El sistema valida el saldo.
Then El sistema informa "Saldo insuficiente para realizar el pago".
Then El sistema no procesa el pago.
Then El cliente puede seleccionar otra cuenta o cancelar.

2. CASO DE USO: OBTENER SALDO DE CUENTA
============================================================

Como cliente autenticado, quiero consultar el saldo de mi cuenta, para conocer cuánto dinero tengo disponible.

ACTORES PRIMARIOS:
- Cliente

ACTORES SECUNDARIOS:
- Sistema de Pagos
- Cuenta de Ahorros
- Cuenta Corriente

PRECONDICIONES:
- El cliente debe estar registrado y autenticado.
- El cliente debe tener al menos una cuenta activa.

POSTCONDICIONES:
- El sistema muestra el saldo actualizado de la cuenta.
- No se modifica información de la cuenta.

FLUJO PRINCIPAL:
Given El cliente está autenticado.
When El cliente selecciona la opción "Consultar saldo".
Then El sistema muestra las cuentas asociadas al cliente.
Then El cliente selecciona una cuenta.
Then El sistema consulta la información de la cuenta.
Then El sistema valida que la cuenta esté activa.
Then El sistema obtiene el saldo disponible.
Then El sistema muestra el saldo de la cuenta al cliente.

FLUJO ALTERNATIVO 1 - CONSULTAR OTRA CUENTA:
Given El cliente tiene varias cuentas.
When El cliente selecciona una cuenta diferente.
Then El sistema consulta el saldo de la nueva cuenta.
Then El sistema muestra el saldo correspondiente.

FLUJO ALTERNATIVO 2 - REGRESAR AL MENÚ:
Given El sistema muestra el saldo.
When El cliente selecciona "Regresar".
Then El sistema no modifica la información.
Then El sistema retorna al menú principal.

EXCEPCIÓN 1 - CUENTA INACTIVA:
Given El cliente selecciona una cuenta inactiva.
When El sistema valida el estado de la cuenta.
Then El sistema informa "La cuenta se encuentra inactiva".
Then El sistema no muestra el saldo disponible para operaciones.

EXCEPCIÓN 2 - ERROR DE CONSULTA:
Given El cliente solicita el saldo.
When El sistema no puede consultar la información de la cuenta.
Then El sistema informa "No fue posible consultar el saldo".
Then El sistema permite intentar nuevamente.

POSTCONDICIONES:

FLUJO PRINCIPAL:

Then El sistema identifica al cliente autenticado.

5. CRUD - ENTIDAD CLIENTE
============================================================

5.1 CREAR CLIENTE

Como administrador, quiero registrar un cliente, para permitirle utilizar el sistema de pagos.

ACTORES PRIMARIOS:
- Administrador

ACTORES SECUNDARIOS:
- Sistema de Pagos
- Base de datos

PRECONDICIONES:
- El administrador debe estar autenticado.
- El cliente no debe existir previamente.

POSTCONDICIONES:
- El cliente queda registrado en el sistema.

FLUJO PRINCIPAL:
Given El administrador está autenticado.
When Selecciona "Crear cliente".
Then El sistema solicita los datos del cliente.
Then El administrador ingresa los datos.
Then El sistema valida los datos.
Then El sistema registra el cliente.
Then El sistema muestra "Cliente creado correctamente".

FLUJOS ALTERNATIVOS:
- El administrador puede cancelar antes de guardar.
- El administrador puede corregir datos que no cumplan las validaciones.

EXCEPCIONES:
- El documento del cliente ya existe.
- Faltan datos obligatorios.

5.2 CONSULTAR CLIENTE

Como administrador, quiero consultar un cliente, para visualizar su información.

FLUJO PRINCIPAL:
Given El administrador está autenticado.
When Busca un cliente por documento.
Then El sistema consulta el cliente.
Then El sistema muestra su información.

FLUJOS ALTERNATIVOS:
- Buscar por otro criterio permitido.
- Regresar al listado de clientes.

EXCEPCIONES:
- Cliente no encontrado.
- Error de consulta en la base de datos.

5.3 ACTUALIZAR CLIENTE

Como administrador, quiero actualizar los datos de un cliente, para mantener su información vigente.

FLUJO PRINCIPAL:
Given El cliente existe.
When El administrador selecciona "Actualizar".
Then El sistema muestra los datos actuales.
Then El administrador modifica la información.
Then El sistema valida los cambios.
Then El sistema guarda la información actualizada.

FLUJOS ALTERNATIVOS:
- Cancelar los cambios.
- Modificar únicamente un dato.

EXCEPCIONES:
- Datos ingresados con formato inválido.
- Cliente no encontrado.

5.4 ELIMINAR CLIENTE

Como administrador, quiero eliminar un cliente, para retirar registros que ya no deban estar activos.

FLUJO PRINCIPAL:
Given El cliente existe.
When El administrador selecciona "Eliminar".
Then El sistema solicita confirmación.
Then El administrador confirma.
Then El sistema elimina o inactiva el cliente.
Then El sistema informa que la operación fue realizada.

FLUJOS ALTERNATIVOS:
- El administrador cancela la eliminación.
- El sistema permite inactivar en lugar de eliminar físicamente.

EXCEPCIONES:
- Cliente no encontrado.
- El cliente tiene información relacionada que impide la eliminación.
